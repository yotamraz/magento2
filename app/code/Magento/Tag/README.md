# Magento_Tag module

Port of the legacy `Mage_Tag` module (magento-lts, AFL 3.0 / OSL 3.0 notice preserved; see `LICENSE.txt` and
`LICENSE_AFL.txt` -- flagged for legal review). This is the foundation milestone: persistence layer only.

## Contents

- `Model\Tag`, `Model\Tag\Relation`, `Model\ResourceModel\Tag`, `Model\ResourceModel\Tag\Relation`,
  `Model\ResourceModel\Tag\Collection`, `Model\Session`, `Helper\Data`.
- Declarative schema (`etc/db_schema.xml` + `etc/db_schema_whitelist.json`) for `tag`, `tag_relation`,
  `tag_summary`, `tag_properties`.
- Frontend route `tag` (id `tag`) and admin route `tag`. No controllers exist yet, so `/tag/` yields the
  standard Magento 404.

## Schema decisions

- Option 1/2 hybrid: column types, defaults, nullability, primary/unique keys, explicit indexes and
  FK delete actions are copied exactly from `sql/tag_setup/install-1.6.0.0.php` (`store_id` stays
  `smallint unsigned`, `status` stays signed `smallint`). Legacy FK/index names were generated by the M1 helper, so
  Magento 2 `referenceId`s follow the Magento 2 convention `<TABLE>_<COLUMN>_<REFTABLE>_<REFCOLUMN>` for foreign
  keys and `<TABLE>_<COLUMN(S)>` for indexes/unique constraints; the physical names are generated by the framework.
- Referenced tables are renamed to their M2 equivalents: `customer/entity` -> `customer_entity`,
  `catalog/product` -> `catalog_product_entity`, `core/store` -> `store`.
- `created_at` is a nullable timestamp (`on_update="false"`), matching legacy "no options" timestamp.
- The legacy `tag` table has no DB unique key on `name`; uniqueness stays an application check
  (`_initUniqueFields`).

## Behavior notes (1:1 port, deviations)

- `Mage::` / `Zend_` access replaced by constructor injection (`StringUtils`, `StoreManagerInterface`,
  `DateTime`, `UrlInterface`, `RelationFactory`). "Is admin store" is `store_id == 0`.
- `Mage_Core_Model_Abstract::_protectFromNonAdmin` on delete is reproduced in `Tag::beforeDelete()` (honours the
  `isSecureArea` registry flag).
- `Relation::addRelations()` keeps the legacy delete condition (not scoped by `tag_id`) deliberately.
- Guards added where PHP 8 would throw: empty `insertMultiple` in `aggregate()`, null `visible_in_store_ids`,
  integer cast of store id in the properties join.
- Not ported (later milestones): indexer (`afterCommitCallback`, `Model\Indexer\Summary`), product/customer/popular
  collections (`getEntityCollection`, `getCustomerCollection`, `getPopularCollection`), event observers, API,
  blocks, controllers, admin menu, layout/templates.
